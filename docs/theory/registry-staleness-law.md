# 注册表陈旧度的一条小定律（2026-11-19）

这不是"新理论"级别的贡献，但它是一个可推导、可检验、能给出设计建议的模型——
是这几天以来第一个真正"公式化"的东西。

## 一、模型

设注册表有 N 个引用。上游撤回（unpublish / rename / yank）按速率 λ（每个引用每单位时间）
发生，近似为泊松过程。注册表每 T 时间做一次全量复查。

一个引用在时刻 t 失效，直到下一次复查才被标记，所以它"已坏但仍在展示"的驻留时间
在 [0, T] 上近似均匀，均值 T/2。

## 二、命题 1（稳态陈旧度）

由 Little 定律，稳态下"已坏但仍在展示"的期望条数为

    E[broken_advertised] = λ · N · T / 2

陈旧比例

    s(T) = λ · T / 2

与 N 无关——陈旧度只由"失效速率 × 复查间隔"决定，跟注册表多大无关。

## 三、命题 2（最优复查间隔）

设每条"已坏但仍展示"的引用每单位时间造成损失 h，一次全量复查的成本为 c·N，
则单位时间总成本

    C(T) = h · λNT/2 + cN/T

对 T 求导置零：

    hλN/2 − cN/T² = 0   ⇒   T* = sqrt( 2c / (hλ) )

最优复查间隔与失效速率的平方根成反比。

这条结论有实际含义：失效快的注册表要查得更勤，但不是线性地勤，而是 1/sqrt(λ)——
所以"每周查一次"对慢速生态足够，对快速生态可能差得远，而"每天查一次"的收益也不是线性的。

## 四、它能预测什么（可证伪）

| 预测 | 检验方式 |
|---|---|
| 当前注册表 T = ∞ → 陈旧度线性增长、无上界 | 已观察：中位条目年龄 218 天，最长 435 天，且零修复 |
| 若改为 T = 1 周，陈旧比例 ≈ λ/2 周 | 需测 λ：12-15 的第二次审计给出每周新增坏引用数 |
| 最优间隔 T* = sqrt(2c/(hλ)) | 需要 c 与 h 的可操作化；可作为敏感性分析 |

证伪条件：若测出的 λ 代入 s(T)=λT/2 后与观测到的陈旧比例相差一个数量级以上，
说明模型错了（很可能因为失效不是泊松、或复查不是全量）——那本身也是结果。

## 五、必须承认的限制

1. 泊松假设未验证。上游撤回可能成簇（一次事件带走一批包），那会让方差远大于泊松。
2. λ 均匀假设。不同命名空间的失效率差异极大（我们的 ranking 里单个命名空间占 14%）。
3. 只建模全量复查。增量复查（只查最近变更的条目）会有不同的 T 结构，这里没覆盖。
4. h 和 c 不可直接观测，所以命题 2 目前是结构性结论（1/sqrt(λ) 的标度关系），
   不是可直接代入的工程参数。

## 六、这是不是"新"

诚实判断：

- 命题 1（s = λT/2）是 Little 定律 + 均匀驻留的直接推论，属于工程界常识。
- 命题 2（T* ∝ 1/sqrt(λ)）同样是标准的新古典库存模型结论（EOQ 的平方根律）。
- 但把它明确地用在"注册表复查策略"上、并给出可测的 λ，据我检索的范围没有见过。

所以准确表述是：这是"把存货模型搬到注册表"的类比推导，不是新理论。
价值在于：它把"该多久查一次"从直觉变成了一个可算的式子，并且给出了要测什么（λ）。
