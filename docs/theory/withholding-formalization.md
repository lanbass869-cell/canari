# 扣留的形式化：承诺时机到底能挡住什么

2026-11-18。这是候选 A 的 Q3（承诺的最小性）的第一次认真形式化。
**结论先说**：能证出一个干净的关系（不可检测的扣留量 = 承诺滞后），但**大概率是
transparency log 领域的老生常谈**，不是新理论。真正属于我们的只有"在真实账本上测量滞后"。

---

## 一、定义

- **收到的记录**：序列 `R = (r_1, …, r_n)`，每条是一份诚实记录（例如一个投票、一次 attestation）。
- **发布**：发布者输出子序列 `S ⊆ R`（保序）。被丢掉的是 `R \ S`，这就是**扣留**。
- **承诺**：在时刻 `t`，发布者公布 `C_t = H(r_1 ‖ … ‖ r_t)`（H 为抗碰撞哈希）。
- **审计者**：只看到 `S` 与若干 `C_t`，不知道 `R`。

## 二、定理 1（承诺窗口内，扣留必被检出）

若发布者公布了 `C_t`，且审计者知道 `t`，则审计者可以：
1. 取已发布集合中属于窗口 `[1, t]` 的那些记录；
2. 按序重算 `H(r_1 ‖ … ‖ r_t)`；
3. 与 `C_t` 比对。

若窗口内有任意一条被扣留，重算的哈希**不等于** `C_t`（由 H 的抗碰撞性）。
因此**窗口内的扣留一定被检出**。

> 注意：这条成立的前提是"发布者无法找到哈希碰撞"，这就是 transparency log 存在的全部理由。

## 三、定理 2（无承诺时，扣留完全不可检测）

若发布者只公布 `S` 与 `H(S)`（即只对**已发布集合**承诺），则对任意 `S`，
两个世界对审计者**不可区分**：

- 世界 1：`R = S`（诚实，没有扣留）
- 世界 2：`R = S ∪ {x}`，其中 `x` 被扣留

两个世界给出的全部观测量相同（同一 `S`、同一 `H(S)`）。审计者无法区分。

**推论**：没有"事前提早承诺"，扣留**在信息论上不可检测**，与样本量、检验方法无关。

## 四、推论（真正有用的那条）

把定理 1 与定理 2 合起来：

> **不可检测的扣留量 = 最后一次承诺之后到达的记录数（承诺滞后）。**

- 若发布者每天承诺一次，则每天最后那一段未承诺的记录可以被任意删改而不被发现；
- 若每次追加都承诺（逐条 Merkle 追加），滞后为 0；
- 若从不承诺，滞后 = 全部。

**这把"要不要承诺"的定性问题，变成了"承诺间隔是多少"的定量问题。**

## 五、诚实的自我评估：这是不是新东西

**大概率不是。**

- 定理 1 就是 transparency log / Certificate Transparency 的立论理由
  （"不承诺就无法发现被扣留的证书"）。
- 定理 2 是"选择偏差使已发布样本不可信"的统计常识在日志场景的复述。
- 推论（滞后 = 不可检测预算）听起来干净，但很可能在可验证日志的文献里是 folklore。

**因此：把这条当"新理论"投稿，风险极高。** 我把它写下来的价值是：

1. 它把问题**钉死**了：扣留的唯一防线是承诺时机，别的都不行；
2. 它给出一个**可直接测量**的量（我们账本的承诺滞后）；
3. 它避免了再去试"更好的统计检验"这条死路。

## 六、属于我们的那一小块（可测量）

把推论用在我们自己的账本上：

- 我们的公开日志**每天**追加一次（GitHub Action）
- 因此**不可检测的扣留窗口 = 每天最后一段未提交的记录**
- 可以量化：取 `docs/log/` 的提交历史，算每次提交之间新增的记录数，
  得到**实际滞后分布**（中位数 / 最大值 / 有多少天滞后 > k）

**这是一个别人没有的数字**：它把"我们的日志能防住多少扣留"从口号变成分布。

## 七、结论与下一步

| 问题 | 答案 |
|---|---|
| 承诺时机是不是关键？ | 是，且可以证明（定理 1/2） |
| 这个证明新吗？ | **大概率不新**（transparency log folklore） |
| 我们真正能贡献什么？ | ①把结论钉死；②**测出真实滞后分布** |
| 还该继续做 A 吗？ | **只做测量部分，不做"新定理"部分** |

## 八、实测：我们账本的滞后是 2 条（2026-11-18）

用 `git log -- docs/log/log.jsonl` 逐提交取行数，得到**每次提交新增的记录数**：

| 指标 | 值 |
|---|---|
| 触碰 log.jsonl 的提交 | 7 次 |
| 当前总记录 | 49 条 |
| 每次新增 | 最少 2 / **中位 2** / 均值 8.0 / **最多 20** |
| 新增 ≥50 条的提交 | 0 次 |
| 最近 6 次 | +20, +2, +20, +2, +2, +2 |

**所以：我们日志的不可检测扣留窗口，中位数是 2 条，最大 20 条。**

**结论（关掉候选 A 的"新定理"部分）**：

- 扣留的防线确实只有承诺时机——这一点已被证明，但**是 folklore**
- 而我们的系统在这个维度上**已经接近最优**：滞后 2 条，不是 2000 条
- 把"扣留"写成论文的主要贡献，等于证明一个已知的 folklore，再配一个很小的测量

**因此候选 A 关闭。** 唯一保留的成果是这段测量，可作为测量论文 Limitations 里的一句话：
> 我们的日志在两次提交之间最多可被扣留 2 条（中位）到 20 条（最大）记录而不被发现，
> 因为不可检测窗口恰好等于承诺滞后。
