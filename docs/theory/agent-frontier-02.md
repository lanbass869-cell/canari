# 候选 F 的形式化：为什么"变笨"和"被压制"分不清

2026-11-18。读透 ACP（2512.07631）的定理 3.1 证明之后，把候选 F 收紧成一个能证的东西。

## 一、先把 ACP 的证明依赖点标出来

定理 3.1 的证明里，两处用到了增益的单调性：

| 位置 | 用到的性质 | 若被破坏 |
|---|---|---|
| **下界** | `μ_i ≤ I_s`（其中 `I_s := μ_1`） | 若后段增益可以**变大**，下界 `C_eff ≤ E[C]` 失效 |
| **上界** | `μ_i ≥ μ_inf`（只需一个**地板**） | 只要有地板就成立，不依赖单调 |

**结论**：单调性只对**下界**承重。所以"攻击者压低增益"**不会**推翻 ACP——
压低增益只是把 `μ_inf` 变得更小，上界变大而已。

**我原来设想的"攻击破坏定理"是错的。** 攻击完全可以在 ACP 的模型内被表达。

## 二、真正的缝在别处：`C_eff` 的基线本身就被污染了

ACP 的核心量是

```
C_eff = (I_total / I_s) · C_s ,  其中 I_s := μ_1
```

注意：**`I_s` 是从同一次运行的第一步测出来的**。

如果攻击者压低了前若干步的增益，那么：

- `μ_1` 被低估 → `I_s` 被低估 → **`C_eff` 被低估**
- 同时 `E[C]` 被抬高
- 观测者看到的"成本超支"（`E[C] − C_eff`）**被两头夹住，反而缩小**

**也就是说：攻击会让"能力不足"的指标看起来更正常。**

## 三、命题 1（齐次压制不可识别）

设攻击对增益做**统一缩放** `μ_i → α·μ_i`（`0 < α < 1`），`I_total` 不变。

则：
- `I_s → α·I_s`
- `C_eff → C_eff / α`
- `E[C] → E[C] / α`（停止时间按 1/α 放大）

因此**比值不变**：

```
E[C] / C_eff  =  常数   （与 α 无关）
```

**推论**：任何只依赖 `E[C]/C_eff` 这一比值的监控指标，**在统一压制下完全失效**——
它看到的与"一个天生就更弱的 agent"一模一样。

## 四、命题 2（非统一压制可检测，但需要知道增益剖面）

若攻击只压低**后段**增益（`μ_i → αμ_i` 仅对 `i ≥ k`），则：

- `I_s = μ_1` 不受影响 → `C_eff` 不变
- `E[C]` 变大 → **比值变大，可检测**

**但这要求观测者知道"前段没被污染"**，即需要一个可信的起点。

## 五、推论（可识别性的最小条件）

> **没有未受污染的基线，任何只依赖本次运行内部统计量的监控，
> 都无法区分"统一压制"与"能力较弱"。**

最小修复：**在受控条件下跑一次 canary 任务，测出 `μ_1^benign`**，
再用它（而不是本次的 `μ_1`）计算 `C_eff`。

## 六、这是不是新东西（自我评估）

**部分新，部分常识。**

- **常识部分**："监控需要干净基线"——这是所有异常检测的常识，不能当贡献。
- **可能新的部分**：这个结论在 **ACP 这个具体框架**里是**新提出的**（框架 2025-12 才出现），
  而且命题 1 给出了一个**精确的不可识别性陈述**（比值不变）。
- **风险**：审稿人可能说"这是 scale-invariance 的平凡推论"。**这个风险是真实的。**

**因此定位**：不是"新理论"，是**"一个 1 个月新的框架里的第一个边界结果"**。
可投 workshop / short paper，不可投顶会正刊。

## 七、下一步（如果继续）

1. 把命题 1 写成严格版本（含停止时间的缩放论证）
2. 找 ACP 论文里"实验验证"部分，用它的公开设置做一次数值确认（比值是否真的不变）
3. 若能确认 → 写成 4 页短文：《Scale-invariant capability metrics cannot detect uniform degradation》

**杀项**：若查重发现已有"efficiency ratio 对均匀缩放不敏感"的既有结论（很可能在
性能监控/软件老化 literature 里），则这条也关。


## 八、杀项结果：候选 F 也关闭（2026-11-18）

**为什么关**：命题 1 是**一行算术**——两个量都乘以 α，比值当然不变。
这不是研究结果，是量纲分析。给"比值对均匀缩放不敏感"起一个定理的名字，
审稿人一句"this is a trivial consequence of scale invariance"就能打回。

**命题 2 同理**：改变增益剖面自然会改变轨迹，这是定义上的直接推论。

**推论（需要基线）**：所有监控都需要干净基线，这是异常检测的常识。

**若把问题做成"非平凡版本"**（多次任务序列里区分"变弱"与"被攻击"），
它立刻落进 **change-point detection / quickest detection** 的成熟框架
——而 ACP 自己在引用 **Lorden 不等式**，说明那条线本来就是它的近邻。

**结论：F 关闭。不是因为它错，是因为它平凡。**

## 九、一条必须记住的教训

> **"论文只有 1 个月新" ≠ "它的空白值得填"。**

新的框架也会立刻引来一批人做最快的推论；我在它边上能看到的缝，
多半是"一行算术"。**新颖性来自问题结构，不来自时间戳。**

这也是今天我第二次犯同类错（第一次是把 arXiv 数量当成领域活跃度）。
两次的共同点：**用一个廉价信号代替了深判断。**
