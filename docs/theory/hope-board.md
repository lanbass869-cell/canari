## 候选 A（最强）：认证型腐败预算下的"扣留攻击"

**来源**：arXiv:2610.10597《Certified Corruption Budgets》，2026-10-06。
**原文自述（作者原话）**：
> "Validity against offline attackers when the bets change with the data remains
> open. **So do withholding attacks, which suppress uncorrupted records.**"

**为什么是真空位**：
- 该文给了 anytime-valid 的腐败容忍度 B̂_t，且上下界匹配 —— 但它只处理**插入伪造**
  与**翻转**，明确把**扣留（suppress）**列为未解
- 扣留与伪造在统计上不对称：伪造是"多出来"，扣留是"少下去"。任何只做上限的容忍度，
  对"少下去"天然不敏感，这是结构性缺口，不是增量改进
- 我查了 `withholding attack`：命中的全是区块链矿池的 block withholding，**没有一篇**做
  "认证记录的扣留攻击"

**可行性**：高。不需要新数学工具，需要的是：把"记录集合"从多重集改为**带承诺的集合**，
再证明扣留可被检测的下界。我们已有可复用的基础设施（Merkle 日志、追加式账本、
离线验证器）。

**两周第一步**：形式化"扣留攻击"的强弱两档（谁扣、扣什么、扣多少能被 B̂_t 吸收），
证明一个"可检测/不可检测"的分界，用我们自己的 6787 条账本做一次可复现仿真。

**杀项（kill criteria）**：若两档里弱档下界是平凡的（扣留任意数量都不可检测），
说明该问题只在强档有意义 → 换候选 B。

## 候选 B：数据依赖下注下的离线攻击者

**来源**：同一篇，同一句的前半段："Validity against offline attackers when **the bets
change with the data** remains open."

**为什么是真空位**：他们的 anytime-valid 结论依赖"事前固定下注"；一旦下注随数据变化，
离线攻击者可以事后挑选下注方向，把任意解释力变成显著。这是**选择偏差**的经典形态，
但在这套认证框架里没有解。

**可行性**：中高。工具是 e-value / betting 理论，文献充足但需要真功夫。

**两周第一步**：构造一个最小反例——给一个数据依赖的下注序列，使 B̂_t 在同一份数据上
既能报"干净"也能报"腐败"，且两者都通过他们的一致性检验。

## 候选 C：在线准入控制的去随机化

**来源**：arXiv:0803.2842 结尾自述："An interesting open problem is to decide if the
algorithm presented here for the admission control problem can be derandomized."

**可行性**：低（对我们是低）。这是纯算法问题，需要条件期望法/近似去随机化的深厚功底，
且 2008 年至今没人做，说明它可能真的难。

**结论**：列出但不推荐。除非有合作者。

## 候选 D：在线预算分配竞争比的 ε 间隙

**来源**：arXiv:2610.41136（2026-10-30）把上界压到 `1-1/e-ε`，作者明确希望后续工作
缩小与 `0.5016` 的差距。

**可行性**：低。这是活跃战场，全世界最强的一组人在做（HZZ24 等），我们没有胜算。

**结论**：不碰。

## 候选 E：移动拜占庭失败的代价权衡规划

**来源**：arXiv:2511.04523（2025-11）future work："studying other planning strategies that
are able to trade off several cost variables behind the reconfiguration"。

**可行性**：中。需要马尔可夫链建模 + 系统部署，我们有工程能力但没有分布式理论积累。

**结论**：备选。

## 真实方案（两周）

**第 1–4 天**：把候选 A 形式化。
- 定义：记录集合 R，认证者看到 R' ⊆ R（被扣留），容忍度 B̂(R')
- 强弱两档：谁知道什么、能扣多少、扣完是否必须仍然自洽
- 产出：一页问题陈述 + 两个小例子（一个可检测、一个不可检测）

**第 5–8 天**：证明分界。
- 目标：给"可检测扣留"的充要条件，或至少一个充分条件 + 一个不可能性
- 若卡住：退到"给出不可检测性的构造"，也是结果

**第 9–12 天**：用真账本验证。
- 用我们 6787 条 attestation + 公开日志，模拟扣留 1%/5%/20% 的记录
- 验证：现有验证器能不能发现？B̂_t 会不会吸收？
- 这一步是**测量**，能独立成文

**第 13–14 天**：判定。
- 若拿到分界 → 写 4 页短文（FSE IVR / 或安全 workshop）
- 若只拿到测量 → 并入测量论文（`paper-skeleton.md` 的 C7）

## 诚实的风险

1. 候选 A/B 都出自**同一篇 6 周前的论文**，可能作者团队正在做，抢先风险真实存在。
   缓解：两周内出结果，且先发 arXiv 预印本。
2. "扣留不可检测"很可能就是答案，那结论会显得弱——但**弱结论也是结论**，且能解释
   为什么现有认证框架必须假设"记录不被扣留"。
3. 我没有读完这两篇的附录证明，A/B 的"未解"判断基于正文的 open 声明 + 一次检索，
   **不是**穷尽检索。
