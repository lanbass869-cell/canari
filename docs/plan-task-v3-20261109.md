## 三、竞争格局结论（基于 17 个项目逐行代码审计）

### Canari 独占的 8 件事（零竞品同时具备）
1. 跨 registry 统一 feed（npm + PyPI + MCP Registry + dsh.so）
2. Supersession 链（supersedes 指针 + content-addressed 文件名 + timestamp）
3. 同作者/名变体失效传播（related_revocations）
4. 消费端安装门禁（is_gate_passing() CLI）
5. 原生 attestation 摄入（npm Sigstore + PyPI PEP 740）
6. 扫描器编排（scanner_adapter.py 接口）
7. 失败透明（feed JSON 公开 error 计数）
8. 开放数据集（CC-BY-4.0 243 bundles）

### 最危险的竞品
| 项目 | 威胁等级 | 为什么 |
|---|---|---|
| mcpcheckup | 高 | 最接近的系统：DSSE+Ed25519+离线验证+15检查+漂移对比+历史+吊销。工程质量最高。但它只管远端 MCP server |
| repo-forensics | 中 | 最深的扫描器（580 regex + 451 rulepack rules + 29 scanners + fail-closed gate）。但没有 ledger/signing/cross-registry |
| agtmls | 中 | 唯一有签名 registry + revocation feed 的。但只服务自己的 33 个 skills |

### 窗口评估
mcpcheckup 已经覆盖了 4/8 个 Canari 的差异化能力（signing, offline verify, drift comparison, history）。
但它明确不做 cross-registry 和 package ecosystems。如果 mcpcheckup 决定扩展范围，Canari 的窗口会急速收窄。
**arXiv 短文必须在 2 周内投出去。**
